# SCIPL website — v2

The build made after the client reviewed the three-identity prototype. Eight
standalone pages, one identity, real logos, real motion. No framework, no
runtime dependencies beyond a pinned motion stack, no build step for anything
except the page shell.

`../prototype/` is left untouched. It is the record of what was shown and what
the feedback was about; nothing here overwrites it.

## Run it

```
python -m http.server 8200      # from this directory
```

then <http://localhost:8200/index.html>.

## Files

```
_shell.html          head, loader, header, menu, footer, scripts — the frame
_pages/<name>.html   the body of one page and nothing else
<name>.html          GENERATED by tools/build_pages.py — do not hand-edit

assets/css/theme.css   tokens: colour, type, space, motion. One identity.
assets/css/site.css    layout and components
assets/js/motion.js    the entrance vocabulary + the intro
assets/js/site.js      content rendering, menu, carousel, filters, lightbox
assets/img/<slug>/     generated project derivatives
assets/hero/           generated hero plates + v<n>.mp4 clips
assets/logos/          generated client logos
assets/brand/          generated SCIPL lockup, colour + knockout
data/                  generated content bundles
data/corrections.js    ⭐ HAND-MAINTAINED — client-name corrections
```

Regenerate, in order:

```
python tools/extract_deck.py         # deck -> content/projects.json + assets/source/
python tools/build_images.py         # source -> prototype derivatives
python tools/build_hero_video.py     # hero-renders/*.mp4 -> web-ready clips
python tools/build_hero.py           # hero plates (+ wires the clips in)
python tools/build_logos.py          # client logos
python tools/build_brand_assets.py   # SCIPL's own lockup
python tools/build_pages.py          # _shell + _pages -> the eight pages
```

`data/corrections.js` is the exception: everything else in `data/` is generated
and must not be hand-edited, but that file exists precisely so a name can be
corrected without touching a generated bundle the next extraction would wipe.

Editing the menu, header or footer means editing `_shell.html` and re-running
`build_pages.py`. That is the whole reason the shell exists: eight copies of a
navigation drift apart the first time one entry changes.

## Motion

GSAP + ScrollTrigger + Lenis, vendored and pinned. One stack, loaded once.

The rule the whole file is built around: **motion enhances, it never reveals.**
GSAP's from-states are driven by requestAnimationFrame, and rAF stalls in a
background tab or on a saturated main thread — that is exactly how a competitor
ships a homepage reading "0 Projects Delivered". `watchdog()` sweeps on
`setTimeout`, which does not stall, and force-completes any entrance whose
trigger is already on screen, at 1.8s and 4s.

## Bugs worth remembering

- **The sector filter appeared to do nothing.** The counter correctly read
  "4 of 21" while all 21 cards stayed on screen. Filtering was never broken —
  the *hiding* was: `.card{display:block}` beats the UA stylesheet's
  `[hidden]{display:none}` on specificity, so setting `el.hidden` had no visual
  effect at all. Fixed with an explicit `.card[hidden]{display:none}`.
- **Four different Sparsh Hospital sites rendered as four identical cards.**
  Cards showed `city`, and all four are "Bangalore"; the locality lives in
  `location`, which the deck writes three different ways ("Hennur Bangalore",
  "Sarjapur, Bangalore", "Bangalore"). `placeOf()` in `site.js` keeps the
  locality and punctuates it consistently. Nothing is invented — the words are
  the deck's.
- **The rule motion.js draws under a section head was maroon**, which is
  invisible on the maroon field band. It now reads `--rule-draw`, which the
  field overrides to gold.

The watchdog rule shaped three other things worth knowing:

- **The hero carousel never shows an empty frame.** The outgoing plate stays
  fully painted underneath for the whole wipe and is only parked once the
  incoming one is covering. The obvious version — reveal the new one, hide the
  old one on a timer — goes black if the transition stalls. It did.
- **The page-transition veil force-sets its own final transform** after 1.2s, so
  a stalled frame loop cannot leave a maroon rectangle over the page.
- **A hero frame is never waiting on its video.** The still is built first and
  stays as the poster; the clip is attached only when its slide is about to be
  seen and fades over the top on `canplay`. If autoplay is refused, if the file
  is slow, if the codec is unavailable — the photograph is simply what you get.

## The intro, and the rule it breaks

Our own reference study is on record against entry gates. This one is built
with guard rails so both hold:

- shown **once per session**, not per page view — so a refresh will *not* replay
  it. **`?intro=1` forces it back** without needing a new tab, which is how to
  show it to anyone.
- hard-capped at ~1.6s regardless of what is still loading
- never shown under `prefers-reduced-motion`
- the document beneath it is complete and readable throughout — the curtain is
  decoration over finished content, not a gate in front of unfinished content
- if the script never runs at all, a CSS bail animation clears the curtain at
  2.6s. A decorative intro must never be able to hold the page hostage.

Two things about how it is wired, both of which were wrong first time:

- **The decision is made in the `<head>`, before first paint**, and recorded as
  `data-intro` on `<html>`; `motion.js` only *runs* it. Deciding it later means
  the page paints and the curtain then drops over it — a flash of the site
  followed by a loader, which is the opposite of the effect.
- **The count runs on `setInterval`, not `requestAnimationFrame`.** The maths is
  time-based either way, but rAF only fires when the compositor produces a
  frame, and this runs exactly while the main thread is parsing and decoding
  everything the page just asked for. Measured on a cold load: the counter still
  read 15% a full second in, because the callback was not being called. Same
  rule as the scroll watchdog — never let a visible value depend on frame rate.

## QA mode

`?qa=1` settles the page into its resting state: no intro, no transition veil,
no entrance mid-flight, and the hero pinned to a fixed height so a tall headless
window photographs the whole page. `&menu=1` opens the navigation, `&y=<px>`
scrolls to an offset.

```
powershell -File ../tools/shots.ps1 -Out <dir>
```

The Chrome extension was unreliable for this project — throttled rAF when the
window is unfocused, CDP screenshot timeouts, stale composites. Headless Edge
with a virtual time budget is deterministic and much faster.

Two traps in this rig, both of which cost time here:

- **Edge returns before the PNG is flushed.** The script waits for the file
  rather than racing it.
- **The headless viewport floors at ~496 CSS px.** Asking for a 390px window
  produces a 390px *crop* of a 496px layout, which looks exactly like a
  horizontal-overflow bug and is not one. Anything narrower than ~500px has to
  be checked in a real browser or through CDP device emulation.

## Measured

Homepage first paint: **20 requests, 833 KB**. After `load`, three more hero
stills (407 KB) and the first clip (594 KB) arrive, settling at 24 requests /
1,835 KB.

That is up from the prototype's 366 KB, and the reason is the thing the client
asked for: the opening frame went from one still photograph to four full-bleed
plates, two of which now move. For context, from the reference study — Padams
36 MB / 72 requests, Depa 6.0 MB / 90, Carl Hansen 828 KB / 39, Snøhetta
196 KB / 24.

The clips are 594 KB and 696 KB for five seconds each, down from 8.8 MB and
9.9 MB as delivered. The second one is not fetched at all until its slide comes
round.

Two known costs, neither hidden:

- `data/site-data.js` is 105 KB and loads on all eight pages, including three
  that do not read a project. Splitting it per page is the obvious next win.
- The 49 client logos are 49 separate PNGs. They are deferred until the band is
  within 600px of the viewport, so they are off the critical path — but vector
  originals from SCIPL would collapse them into one sprite.

## Honesty markers — keep these in production

Anything SCIPL has not supplied renders with a **◇** and a dotted underline
reading "awaiting content from SCIPL". Client names, locations, areas and
photographs are real, from the 2026 profile deck. Sector classification is ours
and needs confirming. Dates, programme, consultants, certifications, team names,
the whole credentials pack and all narrative are marked placeholders. Nothing
invented is presented as fact.
